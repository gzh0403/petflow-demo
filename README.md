This is a public demonstration sample with fictional demo data, not a commercial product. The intended public URL is https://gzh0403.github.io/petflow-demo/.

这是宠物门店产品的 **P2 公开演示样品**：静态网页，全部为虚构的演示数据，**不是商业产品**，也未接入真实支付、短信或微信小程序。预期公开地址：https://gzh0403.github.io/petflow-demo/

## 如何打开

1. 公开演示地址：https://gzh0403.github.io/petflow-demo/ （仓库根目录的 [`index.html`](index.html)）。
2. 本地也可以用浏览器直接打开本目录下的 [`index.html`](index.html)，或用任意极简静态服务打开该目录（例如 `python3 -m http.server`）。**不需要**长期运行的开发服务器，也没有打包步骤。
3. 建议使用最新版 Chrome、Edge、Safari 或 Firefox。演示状态写在当前浏览器的 `localStorage` 中，同一浏览器刷新后仍会保留。

顶部工具条可随时：

- 在 **顾客 / 店员 / 老板** 之间切换（三端共用同一套本地数据，操作会同步）
- 点击 **初始化 / 重置** 恢复初始演示数据（不会改变当前角色）
- 全程可见说明：「品牌与视觉为 P2 提案，待确认，未锁定」

## 建议走查路径

以下四条请依次走一遍。走查前如数据已被改过，先点「初始化 / 重置」。

### 1. 洗美预约并核销（先选宠物）

1. 顾客端：首页或底部「预约」进入填写预约。
2. 先选宠物 **花生**（小型 / 短毛），再选 **基础洗澡**（应显示 ¥88.00），洗美师 **周澄**，今天 **15:00**，提交。状态为「待确认」。
3. 切到店员，打开该预约：确认 → 到店 → 开始服务 → 完成并核销，选择 **次卡核销**（陈夏的基础洗澡次卡）。
4. 再切回顾客，「我的预约」应为「已完成」；「消费记录」里可按花生看到该笔次卡核销。

### 2. 轻量寄养闭环

1. 顾客端：「我的 → 寄养单 → 预约寄养」，选 **豆豆**、空闲的 **A2 阳光标准间**，入住与离店至少间隔 1 晚，提交。
2. 切到店员「寄养看板」打开该单：办理入住 → 写一条日报 → 离店并模拟到店收款。
3. 顾客端可看到日报与已离店状态，消费记录中出现寄养费用。

### 3. 次卡扣次与拒绝规则

- **正常扣次**：路径 1 完成后，陈夏次卡余次减 1。
- **不能重复核销**：店员在已完成的预约详情点「再次核销（演示拒绝）」，应提示已经核销过。
- **余次不能为负**：重置后，店员打开今日「土豆 · 基础洗澡」（服务中），完成并核销时选择王启明余次为 0 的洗澡次卡，应被拒绝，预约保持服务中。也可在顾客「会员 / 我的次卡」演示购卡。

### 4. 冲突拒绝（员工锁、台位锁、笼位按天锁）

- **洗美师时段冲突**：今天 10:00–11:30 林予安已服务豆豆。再为花生向林予安约 10:00，提交（或该时段已被划线禁用）。
- **美容台位冲突**（不是改个名称）：今天 1 号台被大型犬占用。顾客选 **豆豆** + **许晚晚** + 今天，可见 10:00、10:30、11:00 不可选（许晚晚本人此时段空闲，但没有适合大型犬的空闲台位）。
- **寄养按天冲突**：预约寄养时选 **B1 豪华套房** 并使用与阿楞重叠的入住/离店日，提交会被拒绝。看板里占用按「入住日起、离店日不计入」显示。
- **释放**：待确认/已确认预约可取消；已确认可标逾期未到。取消或逾期未到后，同时释放洗美师时段与台位，可重新预约。
